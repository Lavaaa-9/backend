# Architecture and decisions

## Implementation boundary

One organization, a modular Go monolith, PostgreSQL as the source of truth. API and worker are separate commands. The foundation contains `identity`, `facilities`, `patients`, and initial `privacy` responsibilities. There are no competing backends or frontend screens.

Pinned direct dependencies: Go 1.27.4; Fiber v3.7.0; pgx/v5 v5.13.0; Goose v3.30.1; validator/v10 v10.30.6; x/crypto v0.59.0; google/uuid v1.6.0. Fiber v3.7.0's published go.mod requires Go 1.26.0; the chosen compiler meets this requirement. Official binding and validation documentation was checked before implementation. No Fiber v2 or Gin imports.

References: [Fiber validation](https://docs.gofiber.io/guide/validation/), [Fiber binding](https://docs.gofiber.io/api/bind/), [the pinned Fiber module](https://github.com/gofiber/fiber/blob/v3.7.0/go.mod).

## Code ownership

- `cmd/api`: configuration, restricted connection startup checks, HTTP lifecycle, shutdown.
- `cmd/manage`: embedded migrations, development provisioning, database grants and synthetic seed.
- `cmd/worker`: explicit development sink consumer with bounded operations and graceful exit.
- `internal/httpapi`: DTO binding, permission middleware, transport errors, Origin/CORS and cookie policy. No public database entity binding.
- `internal/modules/identity`: account/session policies, administrative invariants and account persistence.
- `internal/modules/patients`: demographic validation, facility policy, optimistic version checks, idempotency and transactional registration. SQL access is in the module repository.
- `internal/modules/facilities`: initial facility administration and timezone validation.
- `internal/modules/privacy`: privileged audit queries with audited access.
- `internal/platform`: pgxpool setup, migrations, append-only audit insertion, database grants and outbox leasing.
- `internal/security`: bounded-format Argon2id hashes and 256-bit random credentials; hashes are compared in constant time.
- `db/migrations`: versioned PostgreSQL schema, embedded in management binary; Goose is the only migration runner.

Typed SQL is currently handwritten behind module repositories and shared platform persistence helpers; sqlc generation is deferred until the next foundation pass. Services own validation, policy and transaction coordination. Do not build generic table CRUD endpoints as a shortcut.

## Transactions and scarce resources

Registration acquires a transaction-scoped advisory lock over actor/operation/key; normalizes and hashes the DTO; replays a stored response or commits patient, audit, outbox and response atomically. The MRN is generated by a database sequence plus uniqueness. Sequence gaps after rolled-back transactions are expected and not reused.

Profile edits use `UPDATE ... WHERE version = expected` and increment the version. Visibility is checked before disclosing version conflicts. Demographic reads and their successful audit entries share a transaction. Failed audit insertion prevents returning protected read data or committing writes.

All staff administrative changes acquire one transaction advisory lock. Last-active-administrator checks and active-state rechecks occur inside it. Account changes increment a version and revoke target sessions. Refresh, login and password updates lock staff before session/token rows, avoiding inverted locking. Refresh reuse commits revocation before returning 401. A session expires absolutely after seven days; rotation never extends that boundary.

Outbox claiming uses `FOR UPDATE SKIP LOCKED`, a 30-second lease, a unique fencing token, five attempts and exponential delays. Expired fifth-attempt leases become visibly failed. Completion verifies a live lease and atomically inserts an idempotent development observation plus completed state. No external operation happens under a lock. A real provider consumer has not been implemented.

## Authorization and credentials

Access credentials are opaque, random 256-bit tokens, not JWTs. Only SHA-256 digests are stored. Algorithm/issuer claim validation does not apply to opaque tokens: credentials are resolved only by this backend's session database, with server-held client type and expiry. Protected requests load current active state, active facility assignments, and permission rows; no role claims are trusted from a client.

Security migration 00003 adds staff_mfa, mfa_recovery_codes, login_challenges, session assurance, audit reasons/facilities and audit seals. The runtime role cannot write seals; owner-authorized management handles sealing. Services coordinate MFA policy/transactions while mfa_repository.go owns SQL persistence.

Argon2id uses x/crypto, version 19, 64 MiB, three iterations, two lanes, a random 16-byte salt and a 32-byte output. Parsing accepts only this bounded parameter format. Runtime hash parameter configuration/upgrades remain pending. MFA now uses challenge-based login, encrypted TOTP secrets, hashed recovery codes, live session assurance and rate-limited management; see SECURITY_PHASE1.md.

Browser refresh is an HttpOnly, SameSite=Strict path-scoped cookie, Secure outside local development/test. Exact allowed Origin is required for web login, refresh and logout. Mobile auth rejects any Origin and returns refresh in JSON for native secure storage. Browser origins must therefore use the cookie flow. CORS is exact-origin allowlisted. Forwarded IP/proxy headers are not trusted; production reverse-proxy rate-limit design is pending.

## Operational limits and formats

JSON bodies are capped at 64 KiB, unknown fields and trailing JSON are rejected, and binding-validation errors map to 400/422. PostgreSQL operations have ten-second request deadlines, UTC sessions, a ten-connection pool and a ten-second statement timeout. Worker contexts do not retain Fiber contexts or buffers. The API startup verifies migration version and rejects excessive database privileges.

Errors have a stable code/message/fields envelope and generated UUID request_id. Logs contain route templates and request metadata, excluding tokens, bodies, search strings and patient notes. API errors suppress database details. Health routes expose no credentials. Metrics, trace instrumentation and performance/load baselines are still pending.

pgx timestamp decoding is explicitly UTC, independent of the host/container timezone. Date-only birth validation uses the configured clinic calendar date, including local midnight/New Year boundaries. Clinic reporting timezone defaults to Africa/Dar_es_Salaam; no reports are implemented yet. Future financial values must use PostgreSQL numeric and decimal-string DTOs. Proposed policy requiring clinic confirmation: TZS amounts rounded to whole shillings at posting, with rounding mode explicitly chosen before M16; no monetary operations currently implement an assumed policy.
